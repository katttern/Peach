I did Lab 9 without a Google Cloud account: nothing is deployed to GCP, I checked gcp/ with terraform init and validate, and ran the app locally the same way Cloud Run would run it.

1. GCP TERRAFORM AND ADR

Commit with gcp/ and the ADR: https://github.com/katttern/Peach/commit/e18ca8fad30ac21ace0a0b975b468c81234f6685
ADR: https://github.com/katttern/Peach/blob/lab9-gcp/docs/adr/0008-gcp-services.md

gcp/ is a separate Terraform config with its own HCP workspace (peach-gcp), so it cannot break the AWS one. It enables the APIs and describes Cloud Run for the API (own service account, min instances 0), Cloud SQL PostgreSQL db-f1-micro with 10 GB SSD in us-central1, the DB password generated by Terraform and stored in Secret Manager, Artifact Registry for the image, and Firebase Hosting for the frontend with /api/** rewritten to Cloud Run.

In the ADR I chose Cloud SQL and plan to stop it when nobody uses it. Spry uses SQL tables and migrations, so Firestore would mean rewriting the whole data layer, and keeping the database on AWS would add about 100 ms to every request. For e-mail I keep SES, and a mail API key would go to Secret Manager. Sign-in (Cognito), the weekly report and the agenda parser stay on AWS.

terraform init -backend=false and terraform validate in gcp/ (full output: https://github.com/katttern/Peach/blob/lab9-gcp/docs/lab9/terraform-init-validate.txt):

Our backend image never had a Lambda adapter (it runs uvicorn on ECS), so the only change was to make it listen on $PORT. 3. COST TABLE

Prices per month (730 h): AWS in us-east-1, GCP in us-central1. Full table: https://github.com/katttern/Peach/blob/lab9-gcp/docs/lab9/answers.md
When the app is used, I assumed 1 request per second, 100 ms each.

Nobody using it for a month:
- AWS as we really have it (ECS Fargate 24/7 $18.02 + load balancer $16.43 + 4 public IPs $14.60 + ECR $0.10): about $49.15
- AWS from Lab 4 (Lambda + paused Aurora): about $0.30
- GCP (Firebase $0, Cloud Run $0, Cloud SQL stopped $0 + 10 GB disk $1.70): about $1.70, or $9.37 if Cloud SQL runs all the time

Profile               | AWS (ours, ECS) | AWS (Lab 4) | GCP, SQL stopped when idle | GCP, SQL always on
Nobody                | $49.15          | $0.30       | $1.70                      | $9.37
Class demos (20 h)    | $49.15          | $1.50       | $1.91                      | $9.37
Office hours (176 h)  | $49.15          | $10.86      | $3.55                      | $9.37
Busy around the clock | $49.15          | $44.43      | $11.60                     | $11.60

Free tier I used: Cloud Run 2M requests and 180,000 vCPU-seconds a month (only "busy" goes over it, $2.24), Firebase Hosting 10 GB stored and 360 MB a day, Artifact Registry 0.5 GB, Secret Manager 6 secret versions (we use 2), CloudFront 1 TB, Lambda 1M requests.

Which is cheaper: compared with what we really run on AWS, GCP is cheaper in all four profiles, because the load balancer and public IPs cost $31 a month even with no traffic. Compared with Lab 4, AWS is cheaper for "nobody" and "demos" (Cloud SQL always pays for its 10 GB disk, even when stopped), and GCP is cheaper for "office hours" and "busy" (one hour of Aurora costs $0.06, one hour of db-f1-micro $0.0105).
The trap on GCP: Cloud SQL never pauses by itself, so if you forget to stop it, you pay $7.67 a month for nothing. On Cloud Run the same happens if you set min instances to 1 or more.
