## Метод

Скрипт [`scripts/agenda_diff.py`](../../scripts/agenda_diff.py) порівнює кожне поле `ai_suggestion` зі
збереженим значенням. Порівнюються `title`, `starts_at`, `duration_minutes`, а також кожне
`topic`, `owner` і `minutes` у темах та `task`, `owner` і `due` у задачах. Кожне поле потрапляє в одну з категорій:

- **unchanged** — значення збережено як запропоновано;
- **changed** — людина замінила непорожнє значення іншим;
- **erased** — людина стерла запропоноване значення;
- **added** — людина заповнила те, що модель лишила порожнім.

`starts_at` порівнюється як момент часу. Модель повертає `…T10:00:00+02:00`, а API зберігає `…T08:00:00Z`: це той самий момент, тож поле вважається незміненим.

```sh
python3 scripts/agenda_diff.py docs/lab6/saved-agendas/0d9c81ba-*.json docs/lab6/saved-agendas/00e85d2d-*.json
```

## Що видно і чого цей diff не показує

- **Лише одна правка на агенду.** Людина виправила одне поле, як у сценарії GIF: тривалість першої теми.
  Решту полів збережено як запропонувала модель.
- **Помилки моделі, які людина не виправила, diff показує як «unchanged».** Так, обидві агенди
  зберегли `due = 2026-11-01` для «до п'ятниці» (неділя; дату вставлено 29.10, тож має бути 2026-10-30).
  Це та сама помилка v2, що й у [test-table.md](test-table.md). Модель також продублювала задачу
  («тарас до пнятниці збирає порівняння з конкурентами» і «порівняння з конкурентами»), а назву зустрічі
  «синк по прайсингу» записала ще й як окрему задачу. Тому частку незмінених полів можна читати
  лише як «людина погодилась із пропозицією», а не як «пропозиція правильна». Правильність
  міряє офлайн-прогін на eval-наборі з еталонами (answers §4, п. 2).
- **Вигадані значення так не порахувати.** Вставлений текст не зберігається (і не логується),
  тож дізнатися, чи було значення в тексті, можна лише з eval-набору, де текст і еталон лежать поруч.
- **Вибірка: 2 агенди** з майже однаковим текстом від одного користувача під час запису демо.
  Це перевірка, що метрика рахується на реальних даних, а не оцінка якості v2.
- **Дані крихкі:** PostgreSQL API — це sidecar без volume, і будь-який деплой backend зітре ці агенди.
  Тому JSON-копії збережено тут.
